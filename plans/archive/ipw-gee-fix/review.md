## HOLD Resolution — Rule 15 GEE degenerate-scores

**Question:** Is the builder's substituted warning-path test for the Rule 15 scenario acceptable, or is it a behavioral regression?

**Determination: The substituted test is correct. This is a structural impossibility, not a behavioral regression.**

**Reasoning:**

1. **What Rule 15 does:** The post-fit degenerate-scores check in `ipw()` fires when `any(scores <= .eps | scores >= 1 - .eps)` — i.e., when the solver returns float-boundary scores. Rule GEE-9 explicitly states that `nleqslv` "uses its own internal step-damping and does not diverge in the same way as bare NR" and that "The post-fit degenerate check in `ipw()` (Rule 15) handles any residual saturation after `nleqslv` returns."

2. **What nleqslv actually does:** The Newton+dbldog global strategy in nleqslv prevents the iterates from flying to the float boundary. When the system has no valid solution (extreme imbalance), nleqslv declares non-convergence (`termcd = 3`) at an iterate where scores are still in (0, 1). This is the correct behavior — the solver does not diverge; it stops early. Rule 15's trigger condition (`scores >= 1 - .eps`) is unreachable on the GEE path with nleqslv.

3. **The spec's test-spec assumption was incorrect:** `test-spec-ipw-gee-fix.md §Degenerate-scores guard — Rule 15 still fires` instructs "Construct a scenario where the post-fit scores are at the float boundary even after nleqslv returns." This construction is not possible in practice — it is based on an assumption about nleqslv behavior that does not hold. The spec itself (GEE-9) is internally consistent with this: by removing the inner guard precisely *because* nleqslv does not diverge, the spec implicitly acknowledges that nleqslv prevents float saturation. The test-spec did not fully follow through on that implication.

4. **The builder's substituted test is correct:** The test at line 2159 verifies that (a) non-convergence warning fires, (b) `test_invariants()` passes, and (c) scores are in (0, 1). This correctly characterizes the actual GEE behavior on extreme-imbalance inputs.

5. **Rule 15 code path is still exercised:** The existing MLE saturation guard test at line 1764 (`"MLE saturation guard triggers surveywts_error_propensity_scores_degenerate (H-6 block 5)"`) confirms the Rule 15 code path is covered via the MLE path. Coverage at 96.28% reflects this.

**Verdict on HOLD:** The test-spec's degenerate-scores scenario was written on an incorrect assumption about nleqslv behavior. The builder correctly identified the impossibility and substituted a behaviorally appropriate test. The implementation is correct. The test-spec should be updated to reflect actual nleqslv behavior (the tester's HOLD disposition option 1).

No implementation change is required. The HOLD is resolved as: test-spec assumption incorrect; builder's substitution acceptable.
