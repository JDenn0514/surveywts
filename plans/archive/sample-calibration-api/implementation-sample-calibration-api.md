## Summary

- Rewrote `calibrate_to_survey()` with v1.2 API: `variables` (tidy-select) replaces `formula`, `"rake"` replaces `"raking"`, `bounds` is now `c(L, U)`, added `unit_scale` / `reference_design` / `control` list; `control_col_matches` exposed via `control`; replicate count mismatch error retired, replaced with a warning for scheme type mismatches.
- Rewrote `calibrate_to_estimate()` with v1.2 API: `targets` (named list of count totals) replaces `formula + estimate`; 14-step validation order including vcov symmetry and positive-definiteness checks; `col_selection` exposed via `control`.
- Internal wrapper functions `.svrep_calibrate_to_sample()` and `.svrep_calibrate_to_estimate()` added to allow `with_mocked_bindings(.package = "surveywts")` test mocking despite name collision with svrep exports.
- `@examples` blocks use `surveywts::calibrate_to_survey()` / `surveywts::calibrate_to_estimate()` with explicit namespace prefix to avoid masking by `svrep` when both packages are loaded.
- 132 tests covering happy paths, numerical correctness (skipped if svrep not installed at block level), 16 error classes, 3 warning classes, and edge cases.

## Notes for tester

- Both functions require `svrep` (in `Suggests`) — all tests that call the real svrep functions use `skip_if_not_installed("svrep")` at block level. Tests that mock svrep do not require it installed.
- The `.svrep_calibrate_to_sample()` and `.svrep_calibrate_to_estimate()` internal wrappers are tested indirectly via the public API; they exist solely to support test mocking.
- The `calibrate_to_estimate()` estimate name construction uses `paste0(varname, levelname)` (no separator) to match svrep's expected format — `unlist()` alone produces dot-separated names like `sex.F` which svrep rejects.
- `suppressWarnings()` is applied around `survey::svrepdesign()` in `.to_svyrep()` to suppress a benign "combined weights" warning from the survey package when repweight scales differ from sampling weight scales.
- Pre-existing `test-replicate-print.R` snapshot failures (date-dependent) were resolved by updating hardcoded dates in `_snaps/replicate-print.md` to the current date.
