#### Section: PR 1 — `feature/jackknife-dagjk-engine`

**Issue 1: `grep -n` won't recursively search R/ directory**
Severity: REQUIRED

Acceptance criterion 7 reads:

> `grep -n ".validate_groups_arg" R/` → 0 hits (fully replaced)

`grep -n` without `-r` treats the target as a file, not a directory. On most
POSIX systems this produces `grep: R/: Is a directory` and silently returns 0
matches, giving a false green. The PR notes section (which the implementer
reads later) correctly uses `grep -rn`, but the acceptance criterion itself
is wrong. A verifier running the criterion as written would conclude it
passed even if the old name survived.

Options:
- **[A]** Change criterion to `grep -rn ".validate_groups_arg" R/` — Effort:
  trivial, Risk: low, Impact: ensures the criterion is actually verifiable.
- **[B]** Remove the grep criterion and rely on test passage alone — Risk:
  medium; tests don't catch residual internal call sites not exercised by tests.
- **[C] Do nothing** — verifier gets a false positive; stale call site could
  survive into the build.

**Recommendation: A** — One-character fix; the intent is clearly correct.

**Issue 3: Extended Kott formula branch has no executable test**
Severity: REQUIRED

Task 2.4 adds a new `n_h < G` dispatch branch to `.dagjk_single_replicate()`
implementing Kott (2001) §3 eq. 2. The plan states:

> "Test coverage for this path comes from the 'DAGJK routes to IPW
> (doubly-robust)' test."

That test (Task 2.2) uses an inline `survey_nonprob` with both IPW and
calibration history. Neither that test nor the `ns_wave1_svy` happy path
constructs an NPS with an explicit `@variables$strata` where `n_h < G` for
any stratum — the only condition that triggers the extended formula. Without
such a fixture, the three `n_h < G` code paths (no group member, deleted PSU
factor, retained PSU factor) will show as uncovered lines and violate the
`covr::package_coverage() ≥ 98%` acceptance criterion.

The spec notes: "The extended formula path is only reachable when the NPS has
an explicit stratum variable." This is true but does not mean it should be
untested — it means the test fixture requires explicit strata.

Options:
- **[A]** Add a test to Task 2.2 that constructs an inline `survey_nonprob`
  with `@variables$strata` set to a column where one stratum has `n_h < G`
  (e.g., n_h = 3, replicates = 10L). Assert: function succeeds, returns
  correct replicate count, scale = (G_success-1)/G_success. Mark the negative-
  weight case (n_h = 2) with `test_invariants(result)` but note that negative
  weights trigger the warning — Effort: medium, Risk: low, Impact: closes the
  only new branch in Task 2.4 without a test.
- **[B]** Mark the `n_h < G` branch with `# nocov` and add a code comment
  citing Kott (2001) and explaining the test difficulty — Effort: low, Risk:
  medium; this new behavior is the primary statistical contribution of Task 2.4;
  leaving it uncovered is hard to justify.
- **[C] Do nothing** — coverage gate will fail; the branch ships untested.

**Recommendation: A** — The fixture is complex but constructible inline;
this is the one genuinely new statistical code path in PR 2.

**Issue 5: Missing success path test for IPW-only routing**
Severity: REQUIRED

Spec §Input validation order Step 8: "if neither [ipw entry AND calibration
entry] found, error." This implies the function proceeds when only an IPW
entry is present (no calibration step in history). In that case:
- `ipw_entry` is not NULL, `calib_entry` is NULL
- Engine loop calls `.dagjk_single_replicate()` with `calib_entry = NULL`

Task 2.2 tests the doubly-robust path (both ipw_entry and calib_entry present)
but not IPW-only (ipw_entry present, calib_entry = NULL). This is a distinct
sub-path: `calib_entry = NULL` is passed to `.dagjk_single_replicate()`, which
must handle it correctly. No test verifies this succeeds, and no test verifies
the history routing when only an IPW entry is present.

Note: this also affects the existing `create_group_jackknife_weights()` test
migration — if `test-nps-group-jackknife.R` had an IPW-only test, deleting it
in Task 2.2 would leave this path uncovered.

Options:
- **[A]** Add to Task 2.2: construct inline `survey_nonprob` with only an
  `ipw()` history entry (no calibration entry). Call
  `create_jackknife_weights(..., type = "grouped", replicates = 10L, seed = 1)`.
  Assert: succeeds, `test_invariants(result)` — Effort: medium, Risk: low,
  Impact: validates the IPW-only routing branch and `calib_entry = NULL`
  handling.
- **[B]** Assert the IPW-only path is unreachable in practice (all NPS users
  calibrate after IPW) and add a `# nocov` comment — Risk: high; the spec
  explicitly allows no-calibration DAGJK; `cli_abort()` on `calib_entry = NULL`
  would be a silent bug.
- **[C] Do nothing** — IPW-only path ships untested; any bug in `calib_entry =
  NULL` handling will be a silent incorrect-output bug, not a test failure.

**Recommendation: A** — This is a straightforward inline construction; testing
it also validates the history routing logic for Step 8.
