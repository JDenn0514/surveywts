# Spec: group-jackknife

**Status:** SPEC_READY
**Spec version:** 1.2 (Stage 3r Pass 2 resolved — 2026-05-28)
**Target version:** 0.2.x (minor bump within Diagnostics/Replicate phase)
**PR range:** Single feature PR targeting `develop`
**Pipeline split:** None — single builder, single tester.

---

## 1. Scope

### In scope

- New exported function `create_group_jackknife_weights()` that produces
  delete-a-group jackknife (DAGJK) replicate weights for non-probability
  samples (NPS).
- `survey_nonprob` is the only supported input class; all other classes error.
- `reference_sample` argument (`survey_taylor`) used to resolve the reference
  probability design. Argument takes precedence over any reference stored in
  the `ipw()` history entry.
- Groups are formed across the **combined** NPS + reference dataset (not
  separately within each sample).
- Binary logistic model is refit in every replicate (no computational shortcut).
- Reference weight adjustment (`w_ref_adj = w_ref * (N_hat - n_nps) / N_hat`)
  applied within each replicate using the NPS count remaining after group
  deletion.
- Optional calibration step (raking or post-stratification) repeated in each
  replicate when detected in the weighting history, consistent with the
  quasi-randomization bootstrap.
- Scaling constants: `scale = (G-1)/G`, `rscales = rep(1, G)`, `mse = TRUE`.
- Second-call overwrite handling with `surveywts_warning_dagjk_repweights_overwritten`.
- History entry appended to `@metadata@weighting_history` on success.
- `seed` argument for reproducible group assignment.
- All new error and warning classes registered in `plans/error-messages.md`.

### Out of scope

- Computational hat-matrix shortcut for GREG/BLUP estimators (Valliant 2009
  §5): applies to OLS/WLS working models only; not applicable to logistic-IPW
  pipeline.
- `survey_taylor` and `survey_replicate` inputs (no design-based interpretation
  of groups for probability samples; existing `create_jackknife_weights()` with
  `type = "random-groups"` covers that use case).
- `weighted_df` and `data.frame` inputs.
- Runtime warning for DAGJK positive bias with doubly robust estimators (HOLD-1
  resolved as documentation-only; see §7).
- Nonsample variance component (Valliant 2009 §5): requires model assumptions
  beyond DAGJK scope; documented limitation only.
- `type = "hybrid"` (stub for future mass-imputation path, not part of this PR).

## 3. Function Contract: `create_group_jackknife_weights()`

### Signature

```r
create_group_jackknife_weights(
  data,
  groups = 50L,
  ...,
  reference_sample = NULL,
  seed = NULL
)
```

### Arguments

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `data` | `survey_nonprob` | — | The non-probability sample design object. Must have an `operation = "ipw"` entry in `@metadata@weighting_history`. `survey_replicate`, `survey_taylor`, `data.frame`, and `weighted_df` all error. |
| `groups` | `integer(1)` | `50L` | Number of random deletion groups $G$. Must be a whole number $\geq 2$. Whole-number doubles are coerced to integer silently. Default of 50 follows Valliant (2020) simulation validation. Must be $\leq$ combined NPS + reference row count. |
| `...` | — | — | Must be empty. Forces all remaining arguments to be named. |
| `reference_sample` | `survey_taylor` or `NULL` | `NULL` | Reference probability sample. When non-`NULL`, overrides any reference design stored in the `ipw()` history entry. `survey_replicate` input errors with `surveywts_error_reference_sample_class`. |
| `seed` | `integer(1)` or `NULL` | `NULL` | RNG seed for reproducible group assignment. When non-`NULL`, `set.seed(seed)` is called once immediately before group assignment. The caller's global RNG state is not restored. |

### Returns

A `survey_nonprob` with:

- $G$ new replicate weight columns added to `@data`, named `repwt_1`,
  `repwt_2`, ..., `repwt_G` (consistent with `create_bootstrap_weights()`
  quasi-randomization naming). If any replicates failed, the successful
  replicates are numbered sequentially from 1.
- `@variables$repweights` populated with the column names of the replicate
  weight columns.
- `@variables$scale` set to `(G - 1) / G` where `G` is the number of
  successful replicates.
- `@variables$rscales` set to `rep(1, G_success)` where `G_success` is the
  number of successful replicates.
- `@variables$mse` set to `TRUE`.
- `@variables$type` set to `"group-jackknife"`.
- A new history entry appended to `@metadata@weighting_history` with
  `operation = "group_jackknife_weights"` and parameters documented in §3.6.
- All other `@variables` keys (`weights`, `fpc`, `fpctype`, `ids`, `strata`)
  are preserved unchanged from the input.

### Replicate weight matrix semantics

For each NPS unit $i$ and group replicate $g$:

- If unit $i$ is **not** in group $g$: replicate weight equals the
  leave-one-group-out pseudo-weight computed from the refitted model on the
  reduced combined dataset (NPS units not in group $g$ + reference units not
  in group $g$).
- If unit $i$ is **in** group $g$: replicate weight is `0`.

### Estimation pipeline per replicate

For replicate $g = 1, \ldots, G$:

1. **Remove** all units assigned to group $g$ from the combined NPS+reference
   dataset. "Combined dataset" is all NPS rows union all reference rows, with
   group membership assigned randomly before the loop.

2. **On the reduced combined dataset** (all units not in group $g$):

   a. Compute reference weight adjustment:
      ```
      N_hat    = sum(w_ref) over all reference units not in group g
      n_nps_g  = number of NPS units not in group g (unweighted count)
      w_ref_adj[i] = w_ref[i] * (N_hat - n_nps_g) / N_hat
      ```
      Applied unconditionally in every replicate (not gated on a 5% fraction
      threshold, unlike the `ipw()` `adjust_reference` logic). The adjustment
      accounts for within-replicate changes to both the reference and NPS
      populations.

      This within-replicate extension of Valliant (2020) Eq. 1 is required for
      DAGJK internal consistency: N_hat and n_nps are recomputed for each
      replicate g using only units not in group g, so the adjustment reflects
      the state of the data actually available in that replicate. This extension
      is not explicit in Valliant (2020) but follows directly from the DAGJK
      replication logic.

      If `N_hat_g - n_nps_g < 0` (within-replicate NPS count exceeds estimated
      population size), this replicate is counted as failed. This can occur when
      the NPS is a very large fraction of the target population — see §6
      Assumption 8.

   b. Refit the binary logistic model using the same `formula`, `method`,
      `estimating_eq`, and `missing_method` recorded in the `ipw()` history
      entry, also using the `maxit` and `epsilon` values from the `ipw()`
      history entry. When `maxit` or `epsilon` is absent from the history entry
      (weights created before this PR), fall back to `25L` and `1e-8`
      respectively. Reference rows get the adjusted weight `w_ref_adj`; NPS
      rows get weight 1.

      **Note:** this requires that `ipw()` records `maxit` and `epsilon` in its
      history entry — this is a modification to `nonprob-ipw.R` required by
      this PR (see §2 Modified files, and the history entry schema in §3.6).

   c. Predict pseudo-inclusion probability $\hat\pi_i$ for each NPS unit not
      in group $g$.

   d. Compute NPS pseudo-weight: $w_i^{(g)} = 1 / \hat\pi_i$. If the
      `trim_threshold` field in the `ipw()` history entry is non-`NULL`, apply
      trimming to replicate pseudo-weights at that resolved threshold. If
      `trim_threshold` is `NULL` (i.e., `trim = FALSE` was used in the original
      `ipw()` call), no trimming is applied inside the DAGJK loop.

      For pre-PR `survey_nonprob` objects where `trim_threshold` was never
      recorded in the history entry, `entry$trim_threshold` evaluates to `NULL`
      in R — the same as when `trim = FALSE` was explicitly used. No explicit
      presence check (`is.element("trim_threshold", names(entry))`) is needed;
      the `is.null()` guard covers both cases correctly.

      The replicate pseudo-weights are scaled by the same normalization
      convention as the full-sample `ipw()` output — if the full-sample weights
      were scaled to sum to an estimated population size `N_hat`, replicate
      weights for surviving NPS units are similarly scaled to the
      within-replicate `N_hat_g` (the sum of the reduced reference weights).
      This ensures `theta_g` and `theta` are on the same scale for the DAGJK
      centering term.

   e. If a calibration step (`operation = "raking"` or `"calibration"`) is
      present in the weighting history after the `ipw()` entry: repeat that
      calibration on the reduced NPS units using the replicate pseudo-weights
      from step (d). When multiple calibration entries follow the `ipw()` entry,
      use the last one (highest step number), consistent with the
      quasi-randomization bootstrap behavior.

      - If `targets_from_reference = FALSE` (or absent) in the history entry:
        the calibration targets are external population constants (Census
        tables, published margins). Reuse them unchanged in every replicate.
        Do NOT re-estimate from the reference.
      - If `targets_from_reference = TRUE`: re-estimate targets from the
        reduced reference replicate. For `type = 'prop'`, re-estimate target
        proportions from the reduced reference. For `type = 'count'`,
        re-estimate target counts (sum of reference weights) from the reduced
        reference. Use the same calibration method (raking, GREG) and control
        parameters from the history entry.

        For the `targets_from_reference = TRUE` raking path, the DAGJK
        reuses the existing `.reestimate_margins_from_reference(calib_entry,
        ref_design, ref_data_g)` helper (defined in `R/replicate-weights.R`),
        where `ref_data_g` is the data frame of reference rows not in group $g$
        (including the reference weight column). The helper interface is
        compatible — it takes the `calib_entry`, the original `ref_design`, and
        the subset reference data frame.

      For `operation = "calibration"` specifically:
      - With `targets_from_reference = TRUE`: pass the reduced within-replicate
        reference design (reference rows not in group $g$) as `reference_design`
        when calling `calibrate()`.
      - With `targets_from_reference = FALSE` (or absent): call `calibrate()`
        with the original `population` targets from the history entry and
        `reference_design = NULL`.

3. **Group $g$ units** receive replicate weight `0`.

4. A replicate is **failed** if the binary logistic model does not converge,
   produces degenerate or missing propensity scores (any $\hat\pi_i$ is NA, or
   any $\hat\pi_i \leq 0$ or $\geq 1$), if the downstream calibration step
   throws an error, or if `targets_from_reference = TRUE` and the calibration
   step fails because group deletion left some reference strata empty (stratum
   depletion). Failed replicates are counted; the replicate weight column for
   that replicate is not included in the output.

**Argument order of validation:**
1. `data` class (via `.validate_replicate_input()` then DAGJK-specific check)
2. `reference_sample` class (if non-`NULL`)
3. `groups` type → whole-number → minimum-value check (`groups < 2` → `surveywts_error_dagjk_groups_too_small`)
4. ipw history presence
5. reference resolution → ceiling check (`groups > combined NPS + reference row count`)

### Warnings

| Warning class | Condition |
|---------------|-----------|
| `surveywts_warning_dagjk_repweights_overwritten` | `@variables$repweights` already populated; existing columns removed before the new replicates are added |
| `surveywts_warning_dagjk_replicates_failed` | More than 10% of $G$ replicates failed to produce valid weights |
| `surveywts_warning_dagjk_negative_replicate_weights` | One or more NPS replicate weights in any column are strictly negative (can occur after downstream calibration) |
| `surveywts_warning_dagjk_small_groups` | `floor(combined_N / groups) < 5` — average fewer than 5 units per group, signalling potential logistic model convergence problems due to small group size |

### Edge cases

| Situation | Specified behavior |
|-----------|-------------------|
| `groups = 1` | Error: `surveywts_error_dagjk_groups_too_small` |
| `groups` is a whole-number double (e.g., `50.0`) | Coerce to integer silently |
| `groups` has a fractional part (e.g., `50.5`) | Error: `surveywts_error_dagjk_groups_not_whole_number` |
| `groups > combined N` | Error: `surveywts_error_dagjk_groups_exceeds_n` |
| A group deletion leaves no NPS units (all NPS in group $g$) | That replicate is counted as failed |
| A group deletion leaves only reference units (no NPS remaining) | That replicate is counted as failed |
| Logistic model fails to converge in replicate $g$ | That replicate is counted as failed; model fit error is caught internally |
| Degenerate or missing propensity scores ($\hat\pi_i$ is NA, or $\hat\pi_i \leq 0$ or $\geq 1$) in replicate $g$ | That replicate is counted as failed |
| $N\_hat\_g - n\_nps\_g < 0$ (NPS count exceeds estimated population in this replicate) | That replicate is counted as failed (prevents negative reference weights) |
| Reference `survey_taylor` strata depleted by group deletion (when `targets_from_reference = TRUE`) | Calibration step errors; replicate is counted as failed |
| Calibration step throws an error in replicate $g$ | That replicate is counted as failed |
| $> 10\%$ of replicates fail | `surveywts_warning_dagjk_replicates_failed` emitted after the loop |
| All replicates fail | Error: `surveywts_error_dagjk_all_replicates_failed` |
| Any replicate weight is negative | `surveywts_warning_dagjk_negative_replicate_weights` after assembling output |
| `data@variables$repweights` already populated (second call) | Warn with `surveywts_warning_dagjk_repweights_overwritten`, then drop old columns and proceed |
| No calibration entry in history | Only the logistic model is refit per replicate; no calibration step is run |
| `reference_sample` supplied and ipw history also has a reference | `reference_sample` argument wins silently (no warning) |
| `seed = 0L` | Valid seed; `set.seed(0L)` is called; function completes successfully |
| `groups` equals combined NPS + reference row count | Each group has exactly 1 unit; most or all replicates fail (each replicate has 0 NPS units if NPS count ≤ `groups`); `surveywts_warning_dagjk_replicates_failed` if > 10% fail; `surveywts_error_dagjk_all_replicates_failed` if all fail |

### History entry

The `"group_jackknife_weights"` history entry appended to
`@metadata@weighting_history` contains:

```r
list(
  step             = <integer>,        # length(history) + 1L before appending
  operation        = "group_jackknife_weights",
  timestamp        = Sys.time(),
  groups           = <integer>,        # G as supplied (before failure counting)
  groups_used      = <integer>,        # G_success (successful replicates)
  groups_failed    = <integer>,        # G - G_success
  seed             = <integer or NULL>,
  scale            = (G_success - 1) / G_success,
  reference_design = <resolved reference design>,  # the reference actually used
  source_design    = .snapshot_variables_for_history(data)
)
```

**Note on `ipw()` history entry:** The DAGJK implementation requires that the
`ipw()` history entry records `maxit`, `epsilon`, and `trim_threshold`. These
fields are added to the `ipw()` history entry by this PR (see §2 Modified files).
`trim_threshold` is the resolved numeric threshold used for trimming (or `NULL`
if `trim = FALSE`), enabling the DAGJK to reproduce trimming exactly in each
replicate.

### Roxygen documentation requirements

- `@family replicate-weights`
- `@export`
- `@param` for all five arguments including `...`
- `@return` describing the `survey_nonprob` structure returned
- `@details` section must include:
  1. **Model refit requirement:** The binary logistic model (and any downstream
     calibration) is refit from scratch in every replicate. Applying full-sample
     pseudo-weights without refitting underestimates variance.
  2. **Scaling factor:** Always `(G-1)/G` where `G` is the number of groups.
     Using total sample size $n$ in place of $G$ would inflate variance estimates
     by approximately $(n-1)/(G-1)$ — a severe overestimate at typical values.
  3. **Groups span both samples:** Random groups are formed across the full
     combined NPS + reference dataset. Dropping only NPS units from group $g$
     while retaining reference units in group $g$ would misspecify the replicate.
  4. **DR estimator bias (HOLD-1 resolution):** When the pipeline applies both
     IPW (quasi-randomization) and a subsequent calibration step (a doubly robust
     estimator), DAGJK standard error estimates are slightly conservative
     (positively biased by approximately 3–5% at $n = 500$ and 2–3% at $n = 1000$;
     Valliant 2020, Table 8). This bias does not vanish as $n$ grows; its cause
     is not established in the literature. No runtime warning is emitted.
  5. **No formal consistency proof:** A formal proof of the consistency of the
     DAGJK for non-probability samples does not exist in the literature (Valliant
     2020, §2.4). Consistency is claimed by analogy to Krewski and Rao (1981).
     Variance estimates should be treated as asymptotically justified
     approximations, not guaranteed-consistent estimators.
  6. **Nonsample variance component:** DAGJK captures only the sample-based
     estimation variance. The nonsample component (uncertainty about unobserved
     population units) is not captured. For probability samples this is handled
     by finite population corrections; no equivalent mechanism exists for NPS.
  7. **Jackknife vs. bootstrap:** The group jackknife is on firmer theoretical
     ground than the bootstrap for NPS variance estimation (Elliott and Valliant
     2017, §4), though neither has a complete asymptotic theory.
  8. **`mse = TRUE` and centering:** `mse = TRUE` centers each replicate
     estimate on the full-sample estimate (the estimate from the current weight
     column in `@data` before any replication), matching the DAGJK formula
     `v_J = (G-1)/G * Σ(theta_g - theta)^2`. Setting `mse = FALSE` (centering
     on the mean of replicate estimates) would produce a different variance
     estimator not justified by the DAGJK literature. When fewer than G
     replicates succeed, the scale is updated to `(G_success - 1) / G_success`
     — a pragmatic approximation that treats the G_success successful replicates
     as the effective G. This approximation is valid when failures are random
     (numerical non-convergence), not systematic. It has no formal justification
     in the jackknife literature; treat the resulting variance estimate as
     approximate when replicates fail.
  9. **Full-sample estimate `theta`:** The full-sample estimate `theta` in the
     DAGJK formula `v_J = (G-1)/G * Σ(theta_g - theta)^2` is the estimate
     computed using the weight column currently in `@data` — which reflects all
     weighting steps applied before calling `create_group_jackknife_weights()`.
     If `ipw()` was followed by `calibrate()`, `theta` is the
     calibration-adjusted estimate. The downstream survey infrastructure uses
     `mse = TRUE` to enforce this centering.
  10. **Degrees of freedom:** The DAGJK variance estimator has degrees of
      freedom `df = G_success - 1`, where `G_success` is the number of
      successful replicates. Downstream inference functions (t-tests, confidence
      intervals) that require degrees of freedom should use `df = G_success - 1`,
      consistent with the standard grouped jackknife result (Krewski and Rao
      1981 analogy).
  11. **Natural group structures:** Elliott & Valliant (2017, §3.1) identify
      recruiting/hosting websites as natural deletion groups for NPS group
      jackknife. This implementation assigns units to groups randomly (via
      `seed`). Users with panel or hosting-website cluster structure should use
      random group assignment as an approximation; a future version may support
      pre-specified group membership vectors.
  12. **Reference sample precedence:** When `reference_sample` is supplied and
      the `ipw()` history also stores a reference design, the `reference_sample`
      argument takes precedence silently. Verify that the supplied reference
      matches the one used in `ipw()` — using a different reference for the
      replicate loop than for the full-sample model produces methodologically
      inconsistent variance estimates.
  13. **Return type and `@variables$type`:** This function returns a
      `survey_nonprob`, not a `survey_replicate`, because DAGJK replicate
      weights are NPS pseudo-weights that must remain associated with the IPW
      weighting pipeline. This is consistent with
      `create_bootstrap_weights(type = "quasi-randomization")`. The
      `@variables$type` field is set to `"group-jackknife"`, a
      surveywts-specific value. Downstream `survey`-package functions expecting
      a standard type (e.g., `"JKn"`, `"BRR"`) will not recognize this value.

## 6. Assumptions and Limitations (spec-level)

These assumptions are reproduced here from the literature synthesis to ground
the implementation contract. They also appear in `@details` (§3.7 above).

1. **MAR given covariates** — The quasi-randomization approach requires that
   pseudo-inclusion probability depends only on observed covariates. The function
   cannot verify this; it is a design constraint.
2. **Common support** — Every population unit must have positive probability of
   appearing in either sample. Violations manifest as extreme pseudo-weights,
   best diagnosed via `ipw()` before calling this function. Common support is
   assessed at the `ipw()` stage on the full combined dataset. Group deletion in
   DAGJK replicates may reduce covariate coverage — a covariate level present
   only in group g becomes unobserved in replicate g, producing extreme
   propensity scores for units with that level. The existing per-replicate
   failure mechanism (degenerate or NA propensity scores) partially captures
   this, but near-degenerate scores (e.g., $\hat\pi_i = 0.001$) pass the
   failure check and produce extreme replicate weights that inflate variance
   estimates. This is expected behavior for DAGJK.
3. **Reference sample quality** — The reference sample must represent the full
   target population. The function cannot detect coverage bias.
4. **Random group assignment** — Groups must be randomly assigned. Ordered or
   systematic assignment may violate the independence assumption.
5. **No formal consistency proof** — Consistency by analogy only (Valliant 2020,
   §2.4).
6. **Hard floor $G \geq 2$** — The DAGJK formula is undefined at $G = 1$.
7. **Random group assignment only (this implementation):** This function assigns
   units to groups randomly via the `seed` argument. While Elliott & Valliant
   (2017, §3.1) identify recruiting/hosting websites as natural deletion groups
   for NPS jackknife, this implementation does not support pre-specified group
   membership vectors. Users with natural cluster structure (panel membership,
   hosting websites) should use random group assignment as an approximation.
   Support for pre-specified groups is a future enhancement.
8. **Small NPS sampling fraction:** The DAGJK variance approximation assumes
   n/N → 0 (the NPS sample is a small fraction of the target population). For
   NPS surveys covering a substantial fraction of the population, the nonsample
   variance component grows and DAGJK increasingly underestimates total
   uncertainty. The function cannot detect this violation.

## 7. HOLD-1 Resolution: DR Estimator Bias

**HOLD:** DAGJK is consistently positively biased for doubly robust estimators
(QR + calibration), with approximately 3–5% SE relative bias at $n = 500$ and
2–3% at $n = 1000$ (Valliant 2020, Table 8). The bias does not vanish as $n$
grows and its cause is not established in the literature.

**Resolution (2026-05-27):** Documentation-only. The bias is documented in
`@details` as a known limitation. No runtime warning (`surveywts_warning_dagjk_dr_bias`)
is emitted. No `allow_dr = TRUE` argument. Users applying DAGJK to doubly
robust estimators should treat resulting SE estimates as slightly conservative.

**Rationale:** The bias is small (2–5%), always in a conservative direction,
and its cause is unknown — not a case where a warning would guide corrective
action. A runtime warning would fire on most NPS pipelines (which typically
apply calibration) and produce alert fatigue without actionable guidance.

## 8. Cross-paper Conflicts Resolved

All three cross-paper conflicts identified in `comprehension.md` are resolved
and codified in this spec:

1. **Scaling factor** — `(G-1)/G` (Valliant 2020), not `(n-1)/n` (Valliant
   2009). The 2009 formula uses $n$ = number of deleted clusters; at the group
   level that is $G$. Using total sample size $n$ inflates variance by
   $(n-1)/(G-1)$. **Implementation: bind `scale` to `(G-1)/G` always.**

2. **Computational shortcut** — The hat-matrix shortcut from Valliant (2009) §5
   applies to OLS/WLS BLUP/GREG models only. For logistic-regression-based IPW
   on NPS (the primary use case), the hat-matrix block is not defined in the
   same way. **Implementation: full model refit is required in every replicate.**

3. **NPS consistency** — "Firmer ground" (Elliott and Valliant 2017) relative to
   bootstrap does not mean a formal proof exists. Both statements are correct.
   **Implementation: document the gap; do not claim consistency.**
