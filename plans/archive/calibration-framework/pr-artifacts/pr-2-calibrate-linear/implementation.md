## Summary

- Implemented `calibrate_linear()` for linear (GREG) and truncated-linear
  calibration following Deville & Sarndal (1992) and Deville, Sarndal & Sautory
  (1993). Supports `data.frame`, `weighted_df`, `survey_taylor`, `survey_nonprob`,
  and `survey_replicate` inputs.
- Fixed a bug discovered during implementation: for `type = "count"`, the
  intercept population total must equal the target N (sum of count marginals),
  not `sum(design_weights)`. The `type = "prop"` case was unaffected (both equal
  `total_w`).
- Fixed `.build_calibration_provenance()` call: `q_weights` must be a numeric
  vector (never `NULL`) for the cross-product computation. Pass `q_for_engine`
  (always-ones vector when `unit_scale = NULL`) to the provenance builder; then
  override `caldata$q_weights <- q_weights_vec` (NULL or user vector) for the
  slot.
- Absolute bounds (`bounds_scale = "absolute"`) implemented via the unit-weight
  trick: normalize base weights to 1, scale population totals by `n / sum(d_k)`,
  run NR engine — output weights ARE the absolute calibrated weights. Requires
  `L < 1 < U` for NR convergence (same as multiplicative bounds after the
  transformation).
- Oracle tests (N1, N2) compared against `survey::calibrate(calfun = "linear")`
  with and without bounds, using `as.numeric(weights(...))` to strip survey's
  `eta` attributes for clean comparison.

## Notes for tester

- The worktree branch (`worktree-agent-a0f823f93fc84cc4b`) was based on an old
  commit (v0.2.0) and required infrastructure files to be copied manually from
  the feature branch. The 102 test failures visible in `devtools::test()` are
  all pre-existing from the old branch state — none are from `calibrate_linear.R`
  or `test-calibrate-linear.R`. All 205 `calibrate-linear` tests pass cleanly.

- `survey::calibrate(calfun = "linear", bounds = c(L, U))` is the survey package's
  truncated-linear implementation; `calfun = "truncated"` does not exist in the
  survey package.

- For `bounds_scale = "absolute"`, bounds must straddle 1 for NR convergence
  (since NR starts at lambda=0 → F(0) = 1). Absolute bounds `[L, U]` with
  `L > 1` will cause NR divergence or a singular Jacobian at the starting point.
  This is a known numerical limitation of the truncated-linear method, not an
  implementation bug.
