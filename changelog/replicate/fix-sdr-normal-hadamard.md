# fix(replicate): forward use_normal_hadamard to the SDR back end

**Date**: 2026-09-04
**Branch**: fix/sdr-forward-use-normal-hadamard
**Phase**: Replicate

## Changes

- Add `use_normal_hadamard` to `create_sdr_weights()`, between `sort_var` and
  `mse`, with the default `FALSE`. The argument reaches
  `svrep::as_sdr_design()` under the same name, so the back end no longer
  always runs at the svrep default (#119). No existing call changes.
- Validate the argument with the new error class
  `surveywts_error_use_normal_hadamard_invalid`. The check runs after
  `.validate_replicates_arg()` and before the `sort_var` NA check, so the
  order of the existing errors does not move.
- Record `use_normal_hadamard` in the `parameters` field of the
  `"replicate_creation"` weighting history entry.
- Correct the published SDR variance formula. The `\deqn` block printed the
  scale factor as `1 / (2R)`; the scale factor is `4 / R`, which is what the
  function has always computed.
- Reword the second bullet of `surveywts_message_replicates_rounded_up`. The
  old text claimed the returned order was the smallest that fits the request,
  which is false on the default path: 64 is returned for a request of 50 while
  56 exists.
- Make the shared `@section Messages` example conditional. `replicates = 100`
  gives 128 columns at the default and 104 at `use_normal_hadamard = TRUE`.
- Record the reversal of decision Q8 of the replicate phase in all three
  places that carried it.
