# docs(docs): cut the four slowest `@examples` blocks to under 5 s each

**Date**: 2026-09-01
**Branch**: docs/examples-runtime
**Phase**: Documentation improvements (plans/doc-examples-overhaul.md, Task 2 / PR 1)

## Changes

- Draft the Section A examples overhaul plan in
  `plans/doc-examples-overhaul.md`: the Task 0 audit of all 23 `@examples`
  blocks, the five-item standard, and five implementation PRs
- Delete the `survey::as.svrepdesign()` call from the
  `calibrate_to_estimate()` example. `survey::svytotal()` on the plain
  `survey::svydesign()` returns the same covariance matrix to every digit,
  and the replicate design cost 66 s of the example's 69 s
- Fix the crossover trap in the `calibrate_to_survey()` example: rake the
  non-probability sample first, then call `create_bootstrap_weights()` with
  `type = "quasi-randomization"`. The default type wraps the sample as a
  simple random sample and returns a `survey_replicate`, which
  `calibrate_to_survey()` rejects
- Set every replicate count explicitly in the four examples instead of
  falling through to the 500 default: 100 for the two probability
  bootstraps, 20 for the control design, 10 for the two
  quasi-randomization bootstraps, 25 for the delete-a-group jackknife
- Add `set.seed()` before the two calls whose randomness comes from
  outside this package, and pass `seed =` to every creator that takes one
- Assign every result and add `summarize_weights()` after it, meeting
  items 1 and 2 of the five-item standard for all four functions
- Record the measurements in the plan and mark Task 1 and Task 2 done.
  Total example runtime for the 23 exported functions falls from 130.53 s
  to 21.10 s, and no example now runs over 5 s
- Record the two surveycore findings from the same audit: the
  `as_svydesign()` bridge is correct, so no issue was needed, and the
  quasi-randomization row misalignment is filed as
  [#102](https://github.com/JDenn0514/surveywts/issues/102)

## Files Modified

- `R/calibrate_to_estimate.R` — `as.svrepdesign()` removed; `set.seed()` and `summarize_weights()` added; the comment now says why the plain design is required
- `R/calibrate_to_survey.R` — the primary design is raked before the quasi-randomization bootstrap; replicate counts set to 10 and 20; `set.seed()` and `summarize_weights()` added; comment explains why the default type fails here
- `R/create_bootstrap_weights.R` — both scenarios assign, seed, and summarize; the quasi-randomization count moves from 200 to 10
- `R/create_replicate_weights.R` — all three scenarios assign, seed where the method takes one, and summarize; the delete-a-group count moves from 50 to 25
- `man/calibrate_to_estimate.Rd`, `man/calibrate_to_survey.Rd`, `man/create_bootstrap_weights.Rd`, `man/create_replicate_weights.Rd` — regenerated by `devtools::document()`
- `plans/doc-examples-overhaul.md` — new plan file; Task 1 and Task 2 checklists marked done with the measured numbers
