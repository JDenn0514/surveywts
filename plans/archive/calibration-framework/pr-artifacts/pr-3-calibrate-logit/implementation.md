## Summary

- Implemented `calibrate_logit()` for logit-bounded calibration following
  Deville, Sarndal & Sautory (1993). Guarantees strictly positive calibrated
  weights. Supports all five input classes (`data.frame`, `weighted_df`,
  `survey_taylor`, `survey_nonprob`, `survey_replicate`), both `type = "prop"`
  and `"count"`, both `bounds_scale = "multiplicative"` and `"absolute"`, and
  optional `unit_scale` for per-unit q_k weighting.
- Fixed an absolute-bounds bug: unlike `calibrate_linear()`, the logit calfun
  requires `L < 1 < U`. For absolute bounds (`bounds_scale = "absolute"`), the
  implementation now normalises the input bounds by `mean_d` (`L_g = L_abs /
  mean_d`, `U_g = U_abs / mean_d`), runs the engine with unit weights and
  scaled population totals, then multiplies the engine output by `mean_d` to
  recover final weights in `(L_abs, U_abs)`. The H_abs test data was updated to
  have `mean_d ≈ 1000` (inside the `(200, 2000)` bounds) so the logit constraint
  `L_g < 1 < U_g` is satisfied.
- `@calibration$lambda` stores the **converged Newton-Raphson** `lambda` vector
  from `.calibrate_nr_engine()` — not a post-hoc linear approximation. Verified
  that NR iterates ≥ 2 for logit (EC4 test).
- No `surveywts_warning_negative_calibrated_weights` warning: logit guarantees
  positive weights by construction (bounds are open interval).
- All error and warning paths from the spec (E1–E23, W1–W3) are covered by the
  dual `expect_error(class=)` + `expect_snapshot(error=TRUE)` pattern.

## Notes for tester

- The logit F-function formula `F(0) = 1` always (verified analytically), so
  NR starting at `lambda = 0` always begins with g-weights = 1 — same as all
  other calibration methods.
- For `bounds_scale = "absolute"` with logit, the bounds `(L_abs, U_abs)` must
  straddle `mean(d_k)` (i.e., `L_abs < mean_d < U_abs`) for the normalised
  logit bounds `L_g < 1 < U_g` to hold. The spec does not validate this
  explicitly; violation will cause NR divergence rather than a user-facing error.
  The H_abs test verifies the happy path with `mean_d ≈ 1000` inside `(200, 2000)`.
- The 3 `R CMD check` notes (`checking hidden files`, `non-portable path`,
  `non-standard top-level`) are pre-existing worktree artifacts and are not
  related to this PR.
